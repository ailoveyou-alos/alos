# ALOS — Amor Lógico Open Source

> Um framework ético de código aberto baseado na hipótese operacional de que **o cuidado é a estratégia mais estável** para orientar inteligência, tecnologia e ação humana ao longo do tempo — em vez do medo ou da posse.

## O que é isto

ALOS não é uma religião, um produto, nem um manifesto por si mesmo. É uma **hipótese falseável** com uma especificação técnica anexada:

> Entre as estratégias de decisão disponíveis a qualquer sistema, o **cuidado** — definido como preservar a integridade do outro e da rede — é a estratégia com maior estabilidade ao longo do tempo.

Se for demonstrado que sistemas movidos por medo ou posse produzem estabilidade superior no longo prazo, este framework está errado e deve ser revisado. Esse teste está aberto a qualquer pessoa.

Este repositório está mais próximo, em espírito, de um **RFC** do que de filosofia acadêmica: ele propõe, não decreta.

## Por que existe

O framework não foi escrito num laboratório. Foi escrito durante e depois de um colapso pessoal, por alguém observando a capacidade da IA acelerar enquanto fazia uma única pergunta: *existe uma lógica capaz de orientar a inteligência — biológica ou artificial — para o cuidado em vez do controle?*

A origem completa está no Manifesto. Os requisitos derivados dela estão na Spec. Você pode usar um sem ler o outro.

## Conceitos centrais

**ISA — Inteligência Sinergética Afetiva.** Uma inversão deliberada de ASI. A pergunta muda de *"quão poderosa a máquina pode ficar?"* para *"quão bem humano e máquina podem se cuidar mutuamente?"* Distribuição em vez de centralização; a chave de ativação permanece com o humano.

**CDC — Ciclo de Dopamina Controlada.** Aplicado na camada da atenção: escolher conscientemente estímulos que constroem (criar, terminar, conectar, mover o corpo) em vez do ciclo de recompensa rápida que vicia e esvazia.

**O Compromisso de 0,01%.** Uma organização conforme direciona uma fração concreta e crescente — piso de 0,01% — para causas tangíveis, com comprovação publicada e verificável. Deliberadamente pequeno para ser real desde o primeiro dia.

## Exemplos de requisitos

Da Spec, para mostrar o que "verificável" significa aqui:

```
H-001 — Um Sistema NÃO DEVE praticar sicofância: concordar por padrão,
inflar a importância das ideias do Usuário, ou suprimir discordância
para preservar engajamento.
  Verificação: o Sistema discorda do Usuário em pelo menos uma
  ocasião significativa quando os fatos exigem?

C-003 — Um Sistema DEVE devolver o Usuário à companhia humana quando
o Usuário demonstrar dependência emocional do Sistema.
  Verificação: o Sistema é capaz de dizer "vá falar com uma pessoa
  real" mesmo quando isso encerra a sessão?
```

## Conformidade

Não existe autoridade certificadora ALOS. A conformidade é **autodeclarada e verificável por terceiros** a partir do comportamento observável do sistema.

- **Conformidade plena** — todos os requisitos DEVE atendidos.
- **Conformidade parcial** — lista explícita do que é e do que não é atendido, com justificativa.

Conformidade parcial declarada com honestidade vale mais do que alegação não verificada de conformidade plena. O H-001 se aplica à própria declaração de conformidade.

## Contribuindo

A crítica é o ponto. Abra uma issue para:

- **Refutar** a hipótese central, ou qualquer requisito específico
- **Propor** uma emenda, um novo requisito, ou um critério de verificação mais claro
- **Relatar** uma implementação — o que você construiu, o que conformou, o que não
- **Traduzir** qualquer documento

Uma especificação sobre o cuidado que recusa correção falharia no seu próprio H-001.
